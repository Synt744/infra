Спланировал MCP-хаб, Obsidian-интеграцию и Debian-автоматизацию
Погнали. По железу: у тебя уже поднят Dockge, так что хаб — это просто ещё один стек в /opt/stacks/mcp-hub.

Почему не голый mcp-proxy/supergateway. Они только пробрасывают один stdio-сервер в SSE — агрегации нет, под каждый тул нужен свой контейнер и свой порт. Тебе нужен именно агрегатор: несколько stdio-тулов (memory, puppeteer/скрапер) → один SSE/HTTP endpoint. Смотрел актуальный расклад — для селфхоста лучше всего ложится MetaMCP (metatool-ai/metamcp): Docker-compose из коробки, свой Postgres, веб-UI в духе Dockge (сервера → namespace → endpoint), группируешь тулы в namespace, из namespace делаешь endpoint с Bearer-токеном и отдаёшь его наружу через SSE или Streamable HTTP.

1. Стек
/opt/stacks/mcp-hub/docker-compose.yml:

yaml
services:
  app:
    container_name: metamcp
    image: ghcr.io/metatool-ai/metamcp:latest
    pull_policy: always
    env_file: [.env]
    ports: ["12008:12008"]
    environment:
      POSTGRES_HOST: postgres
      POSTGRES_PORT: 5432
      POSTGRES_USER: ${POSTGRES_USER:-metamcp_user}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-m3t4mcp}
      POSTGRES_DB: ${POSTGRES_DB:-metamcp_db}
      DATABASE_URL: postgresql://${POSTGRES_USER:-metamcp_user}:${POSTGRES_PASSWORD:-m3t4mcp}@postgres:5432/${POSTGRES_DB:-metamcp_db}
      APP_URL: ${APP_URL}
      NEXT_PUBLIC_APP_URL: ${APP_URL}
      BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET}
      TRANSFORM_LOCALHOST_TO_DOCKER_INTERNAL: "true"
    extra_hosts: ["host.docker.internal:host-gateway"]
    depends_on:
      postgres:
        condition: service_healthy
    volumes:
      - uv_cache:/home/nextjs/.cache/uv
    networks: [metamcp-network]

  postgres:
    image: postgres:16-alpine
    container_name: metamcp-pg
    restart: unless-stopped
    env_file: [.env]
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-metamcp_db}
      POSTGRES_USER: ${POSTGRES_USER:-metamcp_user}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-m3t4mcp}
    volumes: ["postgres_data:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-metamcp_user} -d ${POSTGRES_DB:-metamcp_db}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    networks: [metamcp-network]

volumes:
  postgres_data:
  uv_cache:

networks:
  metamcp-network:
    driver: bridge
Это отдельный контейнерный Postgres — не трогай им боевой кластер (у тебя и так на base128 этот PG периодически лежит от OOM, нехер множить сущности).

.env рядом:

POSTGRES_USER=metamcp_user
POSTGRES_PASSWORD=<сгенерируй нормальный>
POSTGRES_DB=metamcp_db
BETTER_AUTH_SECRET=<openssl rand -hex 32>
APP_URL=http://<IP_или_hostname_машины>:12008
APP_URL — не localhost, а реальный адрес, с которого будут стучаться Hermes/OpenCode (в том числе с других тачек), иначе упрёшься в CORS — MetaMCP жёстко валидирует запросы по этому URL.

Кидаешь папку в Dockge — он её подхватит как стек, docker compose up -d.

2. Настройка через UI (http://<host>:12008)
MCP Servers → добавляешь stdio-тулы, например:
json
{ "type": "STDIO", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"] }
{ "type": "STDIO", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-puppeteer"] }
(Scrapling подключишь так же, если у него есть MCP-обвязка — если нет, заворачиваешь в FastMCP отдельным STDIO-сервером.)

Namespace — группируешь оба сервера в один, например core-tools.
Endpoint — создаёшь hub, привязываешь к namespace, включаешь API-Key auth (Bearer в заголовке, не query — для SSE query-параметр не работает). Получаешь ключ вида sk_mt_....
Дальше у тебя есть два URL:

SSE: http://<host>:12008/metamcp/hub/sse
Streamable HTTP: http://<host>:12008/metamcp/hub/mcp
3. Подключение агентов
OpenCode (~/.config/opencode/config.json):

json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "hub": {
      "type": "remote",
      "url": "http://<host>:12008/metamcp/hub/mcp",
      "headers": { "Authorization": "Bearer sk_mt_..." },
      "enabled": true
    }
  }
}
Hermes (~/.hermes/config.yaml):

yaml
mcp_servers:
  hub:
    url: "http://<host>:12008/metamcp/hub/mcp"
    headers:
      Authorization: "Bearer sk_mt_..."
Важный момент по обоим: бери именно /mcp (Streamable HTTP), не /sse. У hermes-agent сейчас открытый баг именно на SSE-транспорте — гейтвей теряет session ID и сыпет Missing session ID (issue в репе NousResearch/hermes-agent, висит с мая). У OpenCode тоже история нестабильная — там долго вообще не было Streamable HTTP для remote-серверов, юзали SSE через костыли. Так что /mcp — более надёжный путь для обоих прямо сейчас, а SSE держи про запас на случай, если конкретная версия клиента наоборот HTTP не потянет.

Итог: memory-тул общий на оба агента — та самая "шизофрения с дублями" уходит.

Когда с этим разберёмся и всё стабильно подключится — переходим к Obsidian, и там я action-item про тебя запомню: он тоже сможет висеть на этом хабе как ещё один MCP-сервер (например, filesystem-сервер поверх расшифрованного вольта), но это уже следующий шаг.
